同样一个变量名，写在不同位置，可能指向完全不同的东西。搞清楚作用域和生命周期，才能解释「为什么这个变量在函数里改了，外面没变」这类问题。

## 局部变量：函数内声明，函数外看不见

```c
void f(void) {
    int x = 10;      // 局部变量
}

int main(void) {
    printf("%d\n", x);   // 错：x 在这里不存在
}
```

局部变量的生命从声明处开始，到它所在的代码块结束时结束。

**「代码块」比「函数」更细**：

```c
int main(void) {
    {
        int a = 1;
    }
    printf("%d\n", a);   // 错：a 的作用域只是上面那对大括号
}
```

`for` 的括号也是一个块：

```c
for (int i = 0; i < 3; i++) { ... }
printf("%d\n", i);       // 错：i 只在循环内有效
```

这条规则的好处是**变量名可以重复使用而不冲突**（不同块里各管各的），坏处是「想在外面用循环后的 i」会编译不过。

## 全局变量：文件内到处可见

```c
int counter = 0;         // 定义在所有函数外面

void inc(void) { counter++; }

int main(void) {
    inc(); inc();
    printf("%d\n", counter);   // 2
    return 0;
}
```

全局变量在整个文件中都可见，生命周期是**程序运行的全程**。

看起来方便，但要克制。三个问题：

1. **任何函数都能改它**，出了 bug 很难定位是谁改的
2. **初始化顺序**在跨文件时不确定，容易踩坑
3. **命名污染**，大项目里容易重名

**建议：能用参数传的，就不要用全局变量。** 全局只留给真正的全局状态，比如配置项、计数器这类确实全程序共享的东西，并且命名加前缀（`g_counter`）表明身份。

## 静态局部变量：函数内，但活到程序结束

```c
void tick(void) {
    static int calls = 0;    // 只在第一次进入时初始化
    calls++;
    printf("第 %d 次调用\n", calls);
}
```

`static` 修饰局部变量时改变的是**生命周期**，不是作用域：

- 作用域：仍然只在函数内
- 生命周期：整个程序运行期间，值在两次调用之间保留
- 初始化：只执行一次

典型用途是「记住上次的状态」，比如计数、缓存。

**注意：`static` 局部变量不是线程安全的**，多线程下会出问题。现在不用管，知道有这个限制即可。

## 变量的存储区

这个概念解释了很多现象：

| 存储区 | 存什么 | 生命周期 | 初值 |
|---|---|---|---|
| 栈 stack | 局部变量、函数参数 | 函数返回即销毁 | **不确定（垃圾值）** |
| 全局/静态区 | 全局变量、static 变量 | 程序全程 | **自动为 0** |
| 堆 heap | `malloc` 分配 | 手动释放 | 不确定 |

**最重要的推论：局部变量必须手动初始化。** 全局变量和 static 变量会被自动清零，局部变量不会。

```c
int g_count;          // 全局，自动是 0

void f(void) {
    int l_count;      // 局部，是垃圾值
    printf("%d %d\n", g_count, l_count);   // 0 和 ???
}
```

这就是为什么「声明时就赋初值」是一条硬性建议。

## 变量遮蔽（shadowing）

内层变量名和外层重名时，内层会「遮住」外层：

```c
int x = 1;

void f(void) {
    int x = 2;         // 遮蔽了全局的 x
    printf("%d\n", x); // 2
}

int main(void) {
    f();
    printf("%d\n", x); // 1，全局的 x 没变
    return 0;
}
```

**这是 bug 的温床。** 读代码时看到 `x`，你得往上找最近的定义才知道是哪一个。

**规则：不要在函数里用和全局变量同名的局部变量。** 编译器加 `-Wshadow` 会警告：

```bash
gcc -Wall -Wextra -Wshadow code.c -o code
```

## 函数内的变量什么时候销毁

```c
int *danger(void) {
    int local = 42;
    return &local;        // 错：返回局部变量的地址
}
```

函数返回后，栈上那块空间被回收，指针指向的内存已经不属于你。之后访问它是**未定义行为**——可能读到 42，可能读到别的函数留下的数据，也可能崩。

这是 C 里最经典的错误之一。正确做法有三：

1. 让调用者传数组/缓冲区进来，函数往里填
2. 用 `malloc` 在堆上分配（记得 free）
3. `static` 局部变量（不推荐，不线程安全且语义怪）

```c
// 推荐：调用者提供空间
void fill(int *buf, int n) {
    for (int i = 0; i < n; i++) buf[i] = i * i;
}

int main(void) {
    int arr[5];
    fill(arr, 5);        // 安全：内存在 main 的栈上
}
```

## 一个能说明一切的例子

```c
#include <stdio.h>

int g_total = 0;                  // 全局：全程有效，自动为 0

void add_score(int s) {
    int local = s * 2;            // 局部：每次调用重新创建
    static int calls = 0;         // 静态局部：只初始化一次
    calls++;
    g_total += local;
    printf("第 %d 次，本次 +%d，累计 %d\n", calls, local, g_total);
}

int main(void) {
    add_score(10);
    add_score(20);
    return 0;
}
```

输出：

```
第 1 次，本次 +20，累计 20
第 2 次，本次 +40，累计 60
```

三次调用里，`calls` 一直累加（static 特性），`local` 每次重建，`g_total` 全程共享。

**把这三个变量的生命周期对上号，作用域这块就通了。**
