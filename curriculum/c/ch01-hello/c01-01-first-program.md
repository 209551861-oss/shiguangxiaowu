写 C 语言这件事，最容易在一开始就放弃。不是因为难，而是因为**第一节课就要同时面对三样东西**：编辑器、编译器、终端。三者任何一环没配好，屏幕上出现的都是一堆看不懂的红字。

这一节只解决一件事：让一个程序真正跑起来，并且学会看懂它报的错。

## 先跑通，再理解

先别问 `#include` 是什么。先让屏幕上出现一行字。人的学习顺序是「先有反馈，再补原理」，反过来会很痛苦。

一个最小的 C 程序只有四行有效的结构：

```c
#include <stdio.h>

int main(void) {
    printf("hello, c\n");
    return 0;
}
```

保存为 `hello.c`。注意后缀必须是 `.c`，不是 `.txt`、不是 `.cpp`。编译器靠后缀判断语言，`.cpp` 会按 C++ 编译，某些写法会不兼容。

## 每一行到底在做什么

**`#include <stdio.h>`** —— 这不是 C 语句，是给「预处理器」的指令。`stdio` 是 standard input/output 的缩写，里面声明了 `printf` 这个函数的签名。没有它，编译器不知道 `printf` 是什么，会报 `implicit declaration of function 'printf'`。

**`int main(void)`** —— 程序的入口。操作系统启动你的程序时，从这里开始执行。`int` 表示它要返回一个整数，`(void)` 表示不接受参数。写成 `int main()` 在 C 里也能过，但 `(void)` 更明确。

**`printf("hello, c\n");`** —— 向标准输出打印。末尾的 `\n` 是换行符。**这个 `\n` 很容易漏**，漏了之后终端提示符会粘在你的输出后面，看起来像程序没结束。

**`return 0;`** —— 告诉操作系统「我正常结束了」。返回 0 是惯例，非 0 表示出错。这个值可以被 shell 读到，后面写脚本判断成败就靠它。

## 编译与运行

C 不是解释型语言，必须先编译成机器码。用 gcc：

```bash
gcc hello.c -o hello     # 编译，输出可执行文件 hello
./hello                  # 运行（macOS / Linux）
hello.exe                # 运行（Windows，PowerShell 里写 .\hello.exe）
```

**一条命令里两个角色要分清**：`gcc` 是编译器，`hello.c` 是输入，`-o hello` 是指定输出文件名。如果省略 `-o`，gcc 默认生成 `a.out`（Windows 上是 `a.exe`）。

如果你在 Dev-C++ 或 Code::Blocks 里按 F11，本质上就是替你执行了这两步。**建议至少手动敲一次命令**，因为将来出错时你必须知道是哪一步炸的。

## 报错分三层，读法完全不同

这是本节最值钱的部分。C 的报错分三类，处理方式完全不同。

**第一层：编译错误（语法/声明问题）**

```
hello.c:3:5: error: expected ';' before 'return'
```

读法是 `文件名:行号:列号: 错误类型: 描述`。**只看第一行**，因为后面的错误往往是被第一行连带出来的。上面这句的意思很直白：第 3 行第 5 列，在 `return` 之前少了分号。

常见的有：

- `expected ';'` —— 上一行结尾忘了分号
- `'x' undeclared` —— 用了没声明的变量，通常是拼写错或忘写类型
- `implicit declaration of function` —— 忘了 `#include` 对应的头文件
- `stray '\xxx' in program` —— 混进了中文标点，尤其是中文分号和引号

最后这条在初学阶段出现频率极高。**中文输入法下的 `；`、`（`、`"` 和英文的 `;`、`(`、`"` 长得像但编译器不认**。

**第二层：链接错误（找不到实现）**

```
undefined reference to `sqrt'
```

编译通过了，但最后拼装阶段找不到 `sqrt` 的实现。原因是数学库要显式链接：

```bash
gcc calc.c -o calc -lm
```

`-lm` 的意思是「链接 libm（数学库）」。这类错误特征是 `undefined reference to`，看到它就往「缺库」方向想。

**第三层：运行时错误（程序跑起来才炸）**

编译和链接都过了，一运行就崩，或者输出是垃圾值。这类最麻烦，因为编译器帮不了你。典型代表：

```c
int x;
printf("%d\n", x);   // 未初始化的局部变量，输出是不确定的垃圾值
```

`x` 没有赋值，它的内容是栈上残留的字节，每次运行都可能不同。**C 不会帮你清零局部变量**，这是它和很多语言的重要区别。

## 三个立刻会遇到的坑

**没换行**：输出全挤在一行，或者和终端提示符连在一起。补 `\n`。

**中文标点**：报 `stray '\357'` 这类八进制数字的错，几乎百分百是中文符号。把输入法切到英文再改。

**找不到命令**：`gcc: command not found` 说明编译器没装或没进 PATH。Windows 上最省事的是装 MinGW-w64 或直接用 VS Code + C/C++ 插件；不想折腾环境可以先在在线编译器上跑。

## 一个自查习惯

以后每次写完代码，先别急着运行，按这三条扫一遍：

1. 每条语句结尾有分号吗（`#include`、`if`、`for` 的大括号除外）
2. 用到的函数，头文件 include 了吗
3. 括号配对了吗

这三条能挡掉初学者 80% 的编译错误。
