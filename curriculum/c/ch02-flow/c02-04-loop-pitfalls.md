循环写错的后果比语法错误严重：语法错编译不过，循环错是**能跑但结果是错的**，或者**永远跑不完**。

这一节讲循环的三类经典错误，每类都给症状和排查方法。

## 第一类：边界差一（off-by-one）

最典型的场景是「1 到 100 求和」：

```c
int sum = 0;
for (int i = 1; i < 100; i++) sum += i;    // 错：少了 100
for (int i = 1; i <= 100; i++) sum += i;   // 对
```

`<` 和 `<=` 差一个，结果差 100。这种错误不会报错，只能靠对边界值的敏感度。

**防错方法：写下循环后，立刻代入三个值验算**

| 代入值 | 期望 | 检查什么 |
|---|---|---|
| 起始值 | 进入循环 | 下界正确 |
| 终止边界 | 恰好在边界停下 | 上界正确 |
| 边界 ±1 | 不在范围内的不进 | 没多算 |

数组遍历同理：

```c
int a[5];
for (int i = 0; i <= 5; i++) a[i] = 0;   // 错：i=5 时越界
for (int i = 0; i < 5; i++)  a[i] = 0;   // 对
```

数组长度是 5，合法下标是 0..4。**`i <= n` 是最常见的越界写法**，因为人的直觉是「到 5 为止」。

**记忆口诀：数组用 `<`，不用 `<=`。** 只要看到 `i <= arr_len`，几乎肯定是错的。

## 第二类：死循环

症状：程序卡住不动，CPU 占用飙高。

**原因一：循环变量没变**

```c
int i = 0;
while (i < 10) {
    printf("%d\n", i);      // 忘了 i++
}
```

**原因二：条件永远成立**

```c
int i = 10;
while (i > 0) {
    i++;                    // 方向反了，越来越远离 0
}
```

**原因三：浮点累加的精度问题**

```c
for (double x = 0.0; x != 1.0; x += 0.1) { ... }   // 可能永远不相等
```

0.1 在二进制里存不精确，累加 10 次后得到的是 0.9999999999999999，永远不等于 1.0。

**浮点循环不要用 `!=` 或 `==` 做终止条件**，改成计次或范围判断：

```c
for (int k = 0; k < 10; k++) {
    double x = k * 0.1;
}
```

**原因四：`;` 写错位置**

```c
while (i < 10);      // 分号让循环体变成空语句，永远原地打转
{
    i++;
}
```

这个错很隐蔽，因为代码看起来结构完整。**`while(...)` 后面直接跟分号，几乎总是 bug**（除非你在故意等待条件，那也要加注释）。

排查死循环的实用办法：在循环体里加一句打印前 10 次，看变量到底怎么变的。

```c
int guard = 0;
while (cond) {
    if (++guard < 10) printf("DEBUG i=%d\n", i);
    ...
}
```

## 第三类：循环变量用错

**内外层用同一个变量**

```c
for (int i = 0; i < 3; i++) {
    for (int i = 0; i < 4; i++) {   // 内层重名，把外层 i 覆盖了
    }
}
```

现代编译器会警告 `shadow`，但老代码里常见。内层变量名必须不同（`i` / `j`）。

**循环结束后还使用循环变量**

```c
for (int i = 0; i < n; i++) { ... }
printf("%d\n", i);      // 错：i 的作用域只在循环内，编译不过
```

如果确实需要知道循环停在哪，把 `i` 声明到循环外面。

**修改了不该改的变量**

```c
for (int i = 0; i < n; i++) {
    if (a[i] == 0) i++;      // 在循环体里动 i，跳过了元素，逻辑容易乱
}
```

循环变量应该在 `for` 的第三段里变，不要在循环体里偷偷改它。

## 累加与计数：两个模式

**累加**：初值必须是 0（乘法则必须是 1）

```c
int sum = 0;                  // 求和的初值
for (int i = 0; i < n; i++) sum += a[i];

int product = 1;              // 求积的初值
for (int i = 0; i < n; i++) product *= a[i];
```

初值写错是很常见的低级错误：求和写成 `int sum;`（垃圾值），结果随机。

**计数**：条件是「满足什么」

```c
int even_count = 0;
for (int i = 0; i < n; i++) {
    if (a[i] % 2 == 0) even_count++;
}
```

**求最大值**：初值不能是 0，要取第一个元素

```c
int max = a[0];               // 不能写 int max = 0，全是负数时就错了
for (int i = 1; i < n; i++) {
    if (a[i] > max) max = a[i];
}
```

这是「求最大值」最经典的错误：初值设 0，数组全是负数时答案错误。

## 什么时候该拆成函数

当循环体超过 15 行，或者嵌套超过两层，就该把内层逻辑提成函数。

```c
// 之前：两层嵌套 + 一堆逻辑，读到一半就忘了在干什么
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        ...20 行...
    }
}

// 之后：一眼看清结构
for (int i = 0; i < n; i++) {
    process_row(a[i], m);
}
```

**函数名就是注释**，而且拆出去之后可以单独测试。

## 调试循环的固定套路

结果不对时，按这个顺序查：

1. **循环跑了几次？** 在循环体第一行加打印，只打前 3 次和后 3 次
2. **边界值对吗？** 用 n=0、n=1、n=边界 三种输入各跑一次
3. **累加初值对吗？** 求和是 0 吗，求积是 1 吗，求最大是 a[0] 吗
4. **有没有越界？** 把所有 `<=` 换成 `<` 试一次

四条查完，绝大多数循环 bug 都能定位。

## 自查

1. 数组遍历用的是 `<` 不是 `<=` 吗？
2. 每个循环都能证明它会终止吗？
3. 求和初值 0、求积初值 1、求最大初值取首元素——对了吗？
4. `while(...)` 后面有没有误加分号？
